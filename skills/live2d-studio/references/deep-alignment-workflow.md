
# 参考图配准与原版还原（把「像不像」变成可核对的数字）

管这一类任务：用户给了原版立绘／头像参考图，要求「按原版还原」某个重建模型或重绘图（脸、头发、眼睛、发饰的大小与位置），你需要把参考图映射到目标画布坐标系、量化差量、改素材、再用真实渲染复测。适用 Live2D/2.5D 重建、抠图重拼、AI 素材替换等一切「用参考图校准重建结果」的场景。

## 标准流程

1. **先把参考图配准到画布坐标系，再谈任何差量。** 配准必须用**共享特征地标**（两图都能唯一识别的同一特征，例如瞳孔中心），不能只靠轮廓 IoU，也不能只看两个版本模型的一致性（见「硬性规则」）。得到 `canvas = k * ref_px + (ox, oy)` 之后才允许量尺寸。把参考图搬进画布帧要按此式**乘 k（缩小）再平移** —— 误用 `1/k` 放大出的参考帧照样能渲染、能叠加、能出对比图，不报任何错，却让全部逐行/逐点比较悄悄在错的尺度上跑（见 `deep-alignment-registration-and-metrics.md` §5）。
2. **量测优先取与美术无关的量。** 模型侧用 manifest 层 bounds／图层几何（精确已知）；渲染图只在**验证过变换之后**用来量「可见外观」。由「可见皮肤连通域」导出的指标（脸宽、下巴、眼到下巴）会被头发覆盖量污染，改头发前后不可比。
3. **先列差量表，再动手。** 每条差量给「参考值 / 模型值 / 差值（画布像素）」；同一特征至少两个互相独立的指标落在同一差量上，再用放大叠加图目视复核，才允许写进结论。
4. **改素材要新建步骤脚本**，不要就地改已有脚本。改前把 source 图层 + manifest + export 整份备份到 `_backup_pre_<step>/`，让改前版本仍可被渲染做对照。
5. **换新素材时，缩放锚点选「参考图与新素材共有、且不受长发/发饰干扰」的结构**（例如 头顶→刘海下沿 的纵向距离），落位后用两个独立特征交叉验证（发饰中心、脸开口框）。三者互相打架 = 新素材自身比例与原版不同，等比缩放救不回来，如实报告，不要硬凑。
6. **验证用导出件（`export/`）的参数化渲染，不要先用已发布件**；同一套掩膜复测差量，达标后才 publish，并在汇报里明确「未发布」。
7. **工作记录追加到项目既有的 HANDOFF／日志**，不新建 md；写验证方法与真实结果，不附截图、不复制运行日志。
8. **给用户看结论时把对比图直接发进对话**（同尺度并排或放大图），并附磁盘路径与本地渲染 harness 链接 —— 只给路径等于没给，用户会要求重发。

## 硬性规则

- **轮廓 IoU 不能单独定案。** 画布只画到大腿、参考图是全身像时，竖直偏移几乎不可分辨：同一份数据里正确偏移 IoU 0.747，而 75px 外的错误偏移 0.754（只差 0.7%），脚本会欣然返回错的。**配准只用它定尺度，偏移必须由特征地标反解**，或整体改用 `scripts/iris_landmark_register.py`。
- **二次加工的参考图（裁切/缩放过的截图）会给出漂移的配准。** 同一张头像参考图对两个版本模型分别配准出 0.632/(169,30) 与 0.715/(156,17)——因为模型轮廓变了，而不是参考图变了。裁切图的正解是**特征地标 + 面积配对**：在两图里检出同一特征块，按面积配对，尺度 = 特征间距比、原点 = 地标 − 地标/尺度，要求两个地标解出的原点互相吻合（实测吻合到 0.0px；面积比 274/274、357/357 直接证明该裁切图是 1:1 未缩放）。
- **不要假设裁切图被缩放过**，量出来再说；面积比给出缩放比的平方。
- **同一份美术、不同头发覆盖量会给出不同的「可见脸」指标**：同一 face 层在两次渲染里量出 chin_y 215 与 249（差 34px）。跨头发改动比较时只用与头发无关的量（图层 bounds、瞳孔中心、配准地标）。
- **量渲染图之前先验证渲染变换，未验证的截图上一个像素都不可信。** 带适配（fit）的 viewer 里 "zoom 1" 不是 1:1：本 harness 的 `fit = 1.86/canvasH` 使 zoom 1 实际约 0.93 px/画布px，于是同一份正确美术被量成「眉在 y165 而非 138」「眼睛低 27px、小一半」，用户会直接判定数据全错、连带不信你的其他结论。定标：拿渲染 PNG 的不透明像素 bbox 与模型自身 drawable 边界并集（画布坐标）对照，迭代 zoom 到吻合并当场断言（Δ ≤ 2px）；每条截图都打印真实 px/画布比例，非 1:1 的图禁止用于量尺寸。**诊断特征**：两侧 bbox 中心相同、尺寸差一个常数比例 = 纯缩放误差，模型并没有位移。
- **渲染与图层几何打架时，先信图层，再查导出回读。** 导出器会回读每个 ArtMesh 的 bounds 与 PSD 层 bounds 比对（本类导出器自带该告警）；两者吻合即证明 PSD 几何已正确进入 moc3，剩下的差异只可能来自渲染变换或 rig —— 此时绝不要改美术。
- **「框」与「可见范围」必须同类同法比较。** 眼层框含睫毛，天生比可见眼开口宽（实测框 33px vs 开口 23.3px，差 40%）：拿框比开口会得出「眼睛过大」，拿开口比框会得出「眼睛过小」，两个方向都是假的。要比就比同一特征、同一掩膜、同一包含范围（睫毛对睫毛、虹膜对虹膜）。同理，比较**轮廓极值**（头顶、呆毛尖、外沿）时两侧必须用**同类**掩膜：模型侧的图层 alpha 与参考侧的非白描边不是一类，参考图那圈细淡外描边会把自己的轮廓读高，从而让你去「修」一个本来正确的长度。
- **轮廓类校正：逐行缩放比整体等比更贴合。** 「后发偏大／刘海重心偏右」这类需求，一个等比 k 满足不了（头部行需 0.78、披发行需 0.93）：用**逐行横向缩放**（锚点固定取画布中线、只缩不放、行间平滑、颅顶以上整行不动）后各行轮廓可收到 2–6px 内，且重心偏左的发团会被自动右收 —— 配方与三条硬约束见 `deep-alignment-asset-swap-fitting.md` §4。
- **对比图是用户唯一的证据，两侧必须走同一条变换链。** 参考图仿射进画布帧、模型侧用已验证 1:1 的渲染或图层合成；绝不用「各自裁切」的两张截图拼并排 —— 尺度一旦不同，正确的美术也会看起来错。用户说图不对时先复验工具链，不要拿数字反驳用户的眼。
- **「眼睛显小」先按不变量归一再下结论。** 绝对尺寸达标却看着小，通常不是眼睛小而是头/发偏宽：用眼距归一化头宽、用眼开口归一化虹膜再比（本类案例根因是头/发比参考宽 11–28%，而眼距与虹膜位置两侧一致）。
- **颜色掩膜会互相串。** 浅金发高光与肤色无法用颜色区分（都满足 r>225、b>150）；画死在底图上的腮红（r−g 45..64，而全脸中位数 26）无法用阈值干净抠掉，任何采样型补绘都会在掩膜碰到头发处留下色块（阈值扫描、肤色门限、最近邻填充、逐列插值、扩散补绘都会留痕）。
- **先确认参考图本身有没有这个特征。** 原版立绘自己就有腮红时，「还原原版」与「去掉该特征」是互相冲突的要求，必须摆出来让用户裁决，不要静默擦美术。底图烤入的特征若确定要去，结构性做法是把它提升成可开关的独立层（沿用面向参数开关的层命名），而不是在底图上硬擦。
- **交付边界**：被推荐／参考的第三方技能只读使用，未经用户同意不得修改其脚本或文档（改前先问）。被要求「回滚」时精确回到原状、把改过的版本另存可复原副本、并跑语法+功能验证（`py_compile` / `--help` / 真实小样本），如实说明「重构回滚 ≠ 字节级复原」。
- **用户对美术有最终决定权**：如「比原版宽 10% 还是精确一致」这类取舍，给数字 + 渲染让用户选，不要用形容词代替测量。

## 支持文件

- `deep-alignment-registration-and-metrics.md` —— 特征地标配准的完整做法与代码骨架、指标选取表（哪些量抗头发污染、哪些不可比、哪些要归一化）、渲染图变换定标（未验证 1:1 的截图不得量像素）、目视复核套路。
- `deep-alignment-asset-swap-fitting.md` —— 把新素材（AI 生成或重绘）装进既有骨架：头发前/后发的锚点、眼三层重切的锚点与交叉校验、常见比例不匹配的处置。
- `scripts/iris_landmark_register.py` —— 用瞳孔地标把裁切参考图解到画布坐标系：输出 k/offset、两个地标各自的解（必须吻合）与面积比校验。
