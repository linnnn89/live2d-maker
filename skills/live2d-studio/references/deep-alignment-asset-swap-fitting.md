# 新素材装进既有骨架（头发、眼睛）

场景：用户用文生图/AI 重绘产出了新的部件素材（不透明白底或带 alpha、分辨率远高于画布），要求「换成新的试试，尺寸会不会更合适」。素材与画布之间没有既有对应关系，要自己求缩放与落位。同一族操作还包括**素材已落位但轮廓相对参考偏宽／偏高**：此时不改素材，而是按参考轮廓做整体或逐行的形状校正（见 §4）。

## 1. 头发（前发/后发）

**锚点选择**：用「**头顶 → 刘海下沿**」的纵向距离匹配参考图的同一距离。

- 头顶 = 第一条宽度 ≥ 上半部最大宽度 50% 的行（跳过细呆毛）。
- 刘海下沿 = 在脸中线上、**厚度 ≥ 窗口宽（约 40px）的连续覆盖段**的末端 —— 用「厚覆盖」而不是单列像素，避免发丝之间的细缝把下沿判浅。
- 该锚点与长发/辫子/发饰无关，是最稳的一条；实测用它缩放后发际线落在参考值上（差 0.1px）。

**不要用「脸开口」当锚点**：新素材的刘海常有中央发缕横穿脸中线，开口在行剖面里不是一个洞，测出来的「开口宽」会是发缕间的前景距离；同一素材用不同定义会给出 1.9–2.5 的漂移比例。

**后发锚点**：取素材高度 20% 行的宽度匹配「前发落位后的头部发量宽」，顶部比模型头顶高约 10px，水平以脸中线居中。后发必须是最底层，`body/face/eyes` 全在其上。

**交叉校验（必做，两个都要看）**：

1. 发饰（玫瑰/丝带）中心与参考图发饰中心的差；
2. 落位后的「脸开口框」与参考图开口框的差。

若两者与「头部发量宽」的结论互相矛盾（例如按头宽缩放后发饰偏 36px），说明素材内部比例与原版不同构：**如实报告差量并给选项（接受偏移 / 只取素材局部 / 不用该素材），不要用非等比拉伸硬凑**。

**素材侧测量注意**：去白底（抠除）后先确认 alpha 干净；素材自带的发饰会跟着层一起变形与移动，若模型另有独立的发饰层，要在重建时把旧层静音（把 PNG 改名让重建脚本生成空占位层），否则会双发饰——这属于结构性改动，要告知用户并说明可回退。

## 2. 眼睛（三层重切）

规范前提：`eyewhite`（作裁剪蒙版的干净眼眶）→ `irides`（**完整圆形**，被眼白裁剪）→ `eyelash`（**只含上睑/睫毛**）。

**锚点优先级**：

1. **虹膜直径**（首选）：参考图虹膜直径 ↔ 素材虹膜直径 → k。掩膜用同一套青蓝阈值，两侧同源。
2. **可见眼开口宽**（交叉校验）：两者应给出同一个 k（实测两者一致到 0.1%），不一致就说明素材眼型与原版不同。
3. 落位：让**素材虹膜中心**落到参考图实测的虹膜中心上（`offset = target_iris - asset_iris * k`），而不是让包围盒对齐 —— 包围盒受睫毛外挑长度影响。

**素材处理要点**：

- 虹膜：掩膜填洞后拟合圆（质心 + 99 分位半径）画**完整圆**，圆内被睫毛盖住的像素用最近有效邻居（`distance_transform_edt(return_indices=True)`）内插，避免缺口。
- 睫毛：深色且 `(b-r)<15`（排除虹膜蓝青），取带条件用 `y < 虹膜中心 + ~0.45r`。**不要卡在虹膜中心线上**：实测 `+0.05r` 只得到 12 行高的窄带而参考暗部是 16 行，眼睛会整体读成「小圆眼」；放到略低于虹膜中心能保住眼尾那撮睫毛，同时靠色相排除虹膜本体。仍需排除独立的下眼线与下睫毛小尖（闭眼时会撕裂出毛刺）。
- **「改了多少墨」类的量在图层 alpha 上量，不要在渲染图上量**：补墨会改变深色掩膜的连通结构（同一层补墨后渲染图里的暗色连通域从 26px 宽碎成 17px，只剩噪点般的碎块），渲染图只用于目视；包围盒以图层 alpha>128 为准（实测对齐：层 33×17 @(209,147) vs 参考暗部 31×16 @(210,149)）。
- 缩放：**预乘 alpha → LANCZOS → 反预乘**，否则半透明边缘在缩小后出现深色描边。
- `np.dstack` 的结果是 int64，`Image.fromarray` 会报 `Cannot handle this data type` —— 输出前统一 `astype(np.uint8)`。

**验收**：睁眼 / 闭眼 / 视线极限三组渲染，确认眼白不溢出、闭眼无残留虹膜、睫毛不断裂、两眼朝向一致；再用同一套掩膜复测眼位与虹膜直径。

## 3. 只改局部长度（呆毛／发梢外凸）

需求形如「头顶那撮冒出去了」「发梢太长」。**不要整层缩放** —— 那会把发际线、头宽、发饰位置一起动。

1. 先锚定**不动点**：颅顶／发际线弧顶（参考图与模型两侧都能量到；本类案例两侧一致到 0.1px），换算成图层内的行号；凸出量 = 参考地标 y − 当前图层框上沿。
2. 只把「不动点以上的那段」竖向重采样到目标高度，不动点以下**逐像素原样保留**；图层框上沿随之升降，把新 bounds 写回 manifest（旧 bounds 作备份）。
3. 素材侧先出 before/after 预览（底部对齐），确认形状没被压扁、根部无断裂、其余部分与改前逐像素一致。
4. 验收：用**已验证 1:1** 的渲染量内容 bbox 上沿，与参考图同一地标比（本例参考呆毛尖 y38.4；改前 22–23，改后 37–38 ✓）。

## 4. 按行轮廓形变（头发整体偏宽／重心偏左）

需求形如「后发需要缩小」「bangs 整体偏右」。整体等比缩放救不了：头部各行需要约 0.78、披发各行约 0.93，一个 k 满足不了两边。做法是**逐行横向缩放**：

1. 参考侧逐行取轮廓 `[L', R']`；模型侧逐行取「参与形变的层 **+ 脸层**」的 alpha 并集 `[L, R]`（脸也算轮廓的一部分，否则下巴行会被误判成需要放大）。
2. 每行 `k(y) = clip((R'-L')/(R-L), 0.75, 1.0)`，对 k 做 ±10 行滑动平均；映射用 `x' = CNX + (x-CNX)·k(y)`。
3. `y < 颅顶` 的行整行原样复制（呆毛是细卷，逐行宽度匹配无意义；它走 §3 的局部长度流程）。
4. 逐行重采样（线稿用最近邻足够锐）、重算包围盒、写回 manifest；改前先 `_backup_pre_*`。

三条必须守住的：

- **只缩不放（`k ≤ 1.0`）。** 头部以下参考图的不透明轮廓是**身体/裙子**而不是头发，不设上限会把披发放大（实测那些行确实解出 k=1.06）。
- **锚点固定取画布中线，不要按每行的轮廓中心平移。** 映射是用**并集**轮廓解的，而单层自身内容常比并集窄（后发位于头后），按行中心平移会把层内内容整体推歪；以固定中线缩放则只改宽度。
- **行间必须平滑。** 不平滑的逐行 k 会在轮廓上留下横向抖动与阶梯。

副作用正是用户想要的：模型头发重心偏左时，绕固定中线收缩会把左沿推右多于右沿，「缩小」自动带来「整体右移」。

验收：改前后各打一张逐行 `[L..R]` 对照表（本例头部各行差由 −19..−24 / +6..+17 收到 −2..−6 / 0..−6，披发段 1–3px），并出放大叠加图目视确认发丝、辫子、发饰没有被拉扯变形。

## 5. 通用检查清单

- [ ] 素材的可见尺寸（不是包围盒尺寸）对齐到参考图的可见尺寸
- [ ] 落位后的层 bounds 已写回 manifest，manifest 与 PSD 实际层一致
- [ ] 旧层已备份到 `_backup_pre_*`，改前版本仍可渲染
- [ ] 重导出后读一遍 psd2live/标签产出，确认每层 tag/side/参数是你期望的
- [ ] 参数化渲染 before/after 对比图 + 同一套指标复测，未达标不发布
- [ ] 局部长度类改动只动凸出那段像素，不动点以下的像素值与 bounds 保持原值
- [ ] 逐行形变类改动有 before/after 的逐行 [L..R] 对照表，且只在需要缩的行上生效（k 上限 1.0）
- [ ] 睫毛带高度、虹膜墨量这类结论取自图层 alpha，不取自渲染图掩膜
